> 과제는 패들릿으로 접수했습니다. 첨부 자료는 없어서 **메모 · 서식은 모두 가상 예시**입니다(사람 · 시료 · 과제 이름 모두 지어낸 것). 실제 메모를 받더라도 사내 문서라 이 리포에는 넣지 않습니다.

## 내 PC 에서 쓰기 — 웹 주소가 막힐 때 (v2.1)

회사 보안으로 웹 주소가 막혀도 쓸 수 있게 두 가지를 둡니다. **1번을 먼저 권합니다.**

1. **HTML 한 파일(설치 · exe 없음, 권장)** — 도구의 「05 설정 → HTML 한 파일로 받기」(또는 꼬리말 링크)로 `data10-10_회의록요약도우미.html` 한 파일을 받아 PC 에 두고 더블클릭합니다.
   - 화면 · 계산 · 워드 읽기(JSZip)가 모두 이 파일 안에 들어 있어 인터넷 · 설치가 필요 없고 외부 주소를 부르지 않습니다. 로그인 없이 바로 열립니다.
   - 회의록은 그 PC 의 그 브라우저 안에만 저장됩니다. 새 판은 같은 이름으로 덮어쓰면 회의록이 이어집니다(바꾸기 전에 JSON 백업 권장).
   - 파일은 리포의 `dist/` 에 있고, `node scripts/build-single.mjs` 가 index.html · css · js · vendor 를 합쳐 만듭니다(판을 올리면 `bump-version` 이 함께 다시 만듦). 직접 고치지 마세요.
   - **AI 자동 보내기**: 내 PC 의 로컬 LLM(Ollama · LM Studio)은 그대로 씁니다. **사내 AI 서버**는 파일에서 오는 요청에 브라우저가 `Origin: null` 을 붙이므로 서버가 이를 CORS 로 허용해야 합니다. 막히면 설정 화면에 경고가 뜨고, IT 에 허용을 요청하거나 반자동(프롬프트 복사 · 붙여 넣기)을 씁니다.
2. **Non Archive 실행 파일(선택)** — 꼭 exe 가 필요할 때. `tools/local-exe/` 의 `build_exe.bat` 이 PyInstaller **`--onedir --noarchive`**(한 파일 압축 · 자기 풀기 없이 폴더형, 파이썬 모듈은 .pyc 낱개)로 굽습니다. 실행하면 `run_local.py` 가 도구를 이 PC 안에서만 열리는 `http://127.0.0.1:18610/` 로 띄우고 브라우저를 엽니다. Windows 에서 만드는 순서 · 주의는 [tools/local-exe/README.md](tools/local-exe/README.md).
   - 서명 없는 exe 는 회사 보안 정책에 따라 이것도 막힐 수 있습니다(코드 서명 · 보안 예외 신청이 필요할 수 있음).
   - 개발 PC 가 macOS 라 Windows exe 는 만들어 보지 않았습니다. `python3 run_local.py` 로 서버가 뜨고 화면이 도는 것까지 확인했습니다.

HTML 한 파일(file://) · 실행기(127.0.0.1) · 웹 주소는 브라우저 저장소가 서로 따로입니다. 옮길 때는 「05 설정 → 백업 · 옮기기」의 JSON 을 씁니다.

## 로그인 · 사용 승인

- 처음 쓰는 분은 대문의 「회원가입」에서 **회사 메일이나 개인 메일 + 비밀번호**(8자 이상)와 이름 · 소속 · 연락처를 넣고 「가입하고 사용 신청」을 누릅니다. 카카오로 로그인해도 됩니다.
- **관리자가 승인하면** 바로 쓸 수 있습니다. 관리자는 오른쪽 위 「구성원 관리」에서 승인 · 사용 중지를 하고, 「관리자로 지정」한 사람도 팀원을 승인할 수 있습니다. 처음에는 강사 계정이 관리자이고, 요청자를 관리자로 올리면 요청자가 자기 팀을 승인합니다.
- 로그인 정보만 Supabase 표 `data1010_members` 에 남습니다. **업무 자료는 서버로 보내지 않고** 이 브라우저(localStorage)에 저장합니다 — JSON 백업을 받아 두세요.
- 내 PC(`localhost` · `127.0.0.1` · 파일로 열기 · HTML 한 파일)에서는 로그인을 건너뜁니다. 내 PC 에서 로그인 화면을 보려면 주소 끝에 `?auth=1` 을 붙입니다.

## 실행 방법

**온라인에서 바로 보기: https://data10-10.jobability.co.kr/**

처음 열면 「00 한눈에 보기」입니다. **예시 메모 3개** 중 하나를 누르면 「01 메모 → 회의록」에 메모와 맞는 서식이 들어갑니다. 「AI 없이(규칙 초안)」 탭의 **「규칙으로 초안 만들기」** 를 누르면 바로 회의록 편집 화면이 열립니다.
실제로 쓸 때는 ① 서식 고르기(우리 팀 워드 양식이 있으면 「04 서식 관리」에서 .docx 로 서식 만들기) → ② 메모 붙여 넣기 또는 .txt · .docx 고르기 → ③ 이름 가리기 확인 → ④ 세 가지 방법 중 하나로 정리 → 편집 · 내보내기 순서입니다.

내 PC 에서 열려면 위 「HTML 한 파일」을 받아 더블클릭하거나, ZIP 을 풀고 `index.html` 을 더블클릭합니다(설치 · 인터넷 필요 없음). 외부 CDN 을 부르지 않습니다(워드 읽기는 `vendor/` 의 JSZip).

### 정리하는 세 가지 방법

| 방법 | 메모가 가는 곳 | 하는 법 |
|---|---|---|
| 반자동(기본) | 사용자가 붙여 넣은 AI 한 곳 | 「프롬프트 복사」 → 회사가 허용한 AI 에 붙여 넣기 → 답을 붙여 넣고 「답으로 서식 채우기」. 이름 가리기를 켜 두면 「인물1」 처럼 가려서 보내고 답은 이름으로 되돌립니다 |
| 로컬 LLM 자동 보내기 | **내 PC 안**(Ollama · LM Studio) | 「05 설정」에서 서버 종류 → 모델 목록 불러오기 → 저장. 「설정한 AI 서버로」 탭에서 버튼 한 번 |
| AI 없이 규칙 초안 | 어디로도 안 감 | 「결정 · 확정 · 하기로」 줄 → 결정 사항, 담당(이름 · @이름 · 담당:)이나 기한(10/24 · 다음 주 금요일)이 붙은 할 일 줄 → Action Item, 「다음 회의」 줄 → 다음 회의. 문장 요약은 하지 않습니다 |

### 로컬 LLM 으로 쓰기 (사내 문서를 외부 AI 에 넣을 수 없을 때)

로컬 LLM 은 내 PC 에서 돌아가는 AI 입니다. 메모가 PC 밖으로 나가지 않습니다. 이 도구는 **OpenAI 호환 주소**(`…/v1/chat/completions`)로 보내므로 Ollama · LM Studio · 사내 LLM 서버 모두 같은 방법으로 붙습니다.

1. **설치** — [Ollama](https://ollama.com) 또는 [LM Studio](https://lmstudio.ai). 회사 PC 라면 설치 가능 여부를 IT 에 먼저 확인합니다.
2. **모델 받기** — 한국어를 잘 하는 모델을 받습니다. 예) `ollama pull qwen3:8b` (메모리 16GB 이상 권장, 8GB 면 더 작은 모델). LM Studio 는 화면에서 모델을 내려받고 Developer 화면에서 서버를 켭니다.
3. **도구를 파일로 열기** — HTML 한 파일(또는 ZIP 을 풀고 `index.html`)을 더블클릭(file://). LM Studio 는 서버 설정의 **「Enable CORS」** 를 켭니다. Ollama 가 연결을 거절하면 환경 변수 `OLLAMA_ORIGINS` 에 허용할 출처를 넣고 다시 켭니다(실제 Ollama 로 끝까지 보내는 확인은 아직 하지 않았습니다).
4. **연결** — 「05 설정 → AI 연결 설정」에서 서버 종류를 고릅니다.
   - Ollama: `http://localhost:11434/v1`
   - LM Studio: `http://localhost:1234/v1`
   - 사내 LLM 서버: 담당 부서에서 받은 주소(보통 `…/v1` 로 끝남)
   「모델 목록 불러오기」 → 모델 고르기 → 「연결 확인」 → 「저장」. 로컬 LLM 은 키를 비워 둡니다.
5. **보내기** — 「01 메모 → 회의록」 4번의 「설정한 AI 서버로(로컬 LLM)」 탭 → 「설정한 AI 서버로 보내기」.

- 온라인 주소(https://data10-10.jobability.co.kr/…)에서도 크롬 · 엣지는 `localhost` 로 보낼 수 있지만, 그때는 Ollama 에 `OLLAMA_ORIGINS` 설정이 필요합니다. **파일로 여는 것이 가장 쉽습니다.**
- Qwen3 처럼 「생각하는 모드」가 있는 모델이 답 앞에 붙이는 `<think>…</think>` 는 도구가 떼고 답만 씁니다.
- 작은 모델은 담당 · 기한을 틀리기 쉽습니다. 편집 화면의 **「확인 필요」**(메모에 없는 담당 · 기한 · 결정)를 꼭 확인하세요.

| 화면 | 하는 일 |
|---|---|
| 00 한눈에 보기 | 흐름 4단계, 저장한 회의록 · 남은 할 일 · 기한 지남 · 3일 안 기한 수, 예시 메모 3개, 세 가지 방법 비교 |
| 01 메모 → 회의록 | ① 서식 고르기(칸 미리 보기) ② 메모 넣기(붙여 넣기 · .txt UTF-8/ANSI · .docx, 회의일) ③ 이름 가리기(이름 찾기 · 켜고 끄기 · 더하기 · 대응표 · 남은 이름 점검) ④ 정리하기 — 반자동 · 설정한 AI 서버(로컬 LLM) · AI 없이 규칙 초안. 작성 중 메모는 새로고침해도 남음 |
| 회의록 편집 | 칸별 편집(목록 칸은 한 줄 한 항목), Action Item 표(할 일 · 담당 · 기한 · 완료 · 더하기/지우기), **메모 근거 점검**(메모에 없는 담당 · 기한, 메모와 많이 다른 결정 · 할 일 문장), 메모 원문 대조, 저장 · Word(.doc) · 인쇄/PDF · 글 복사 · 지우기 |
| 02 회의록 목록 | 회의일 순, 찾기(회의명 · 내용 · 담당자), 할 일 남은 수 · 기한 지남 표시 |
| 03 Action Item | 모든 회의록의 할 일을 기한 순으로 — 남은 할 일 · 기한 지남 · 전체 · 완료, 담당자로 거르기, 「N일 지남 · 오늘 · N일 남음」, 완료 체크(그 회의록에 저장), 글 복사 |
| 04 서식 관리 | 기본 3종(일반 회의 · 시험·검증 결과 리뷰 · 일정 점검), 칸 이름 · 역할 · 모양 · 도움말 편집, 순서 바꾸기, 복사 · 기본값으로, **워드 양식(.docx) · 양식 글로 새 서식 만들기** |
| 05 설정 | **HTML 한 파일로 받기**(쓰는 법 · 실행 파일 안내), AI 연결(OpenAI 호환 주소 · 모델 목록 · 본인 키 — 기억은 선택), 로컬 LLM 준비 안내, 늘 가릴 이름 · 가리기 기본값 · 메모 원문 저장 여부, 백업(.json) 받기 · 불러오기 · 모두 지우기 |

- 로직 테스트: `node test/logic.test.mjs` (26개 — HTML 한 파일이 낡지 않았는지 · 외부 파일 없음 · 같은 판 · 스크립트 끊김 없음도 봄) · `node test/ai-endpoint.test.mjs` (14개) — 의존성 없음
- HTML 한 파일: `node scripts/build-single.mjs` (만들기) · `--check`(지금 소스와 같은지)
- **판 올리기(고칠 때마다)**: `node scripts/bump-version.mjs 2026-10-28.1` — index.html 의 모든 js·css `?v=` · logic.js · app.js 를 같은 값으로, HTML 한 파일(dist)도 다시 만듦. 브라우저가 옛 파일과 새 파일을 섞어 쓰지 않게 하고, 섞이면 화면이 「새 판이 나왔습니다 — 새로고침(Ctrl+F5)」로 멈춥니다. `--check` 로 같은지만 봅니다(로직 테스트도 봄)
- 화면 점검(개발용): `PLAYWRIGHT=<playwright 폴더> node scripts/browser-check.cjs` — file:// 로 1280 · 390 · 360px 에서 흐름 전체를 눌러 봄. `SINGLE=1` 이면 HTML 한 파일을 http · https 요청을 끊고, `BASE=http://127.0.0.1:18610/` 이면 실행기 주소로
- 예시 파일 다시 만들기: `python3 scripts/make-samples.py` → `samples/` 4개 (python-docx 필요)
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py`

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 메모장 · 워드 회의 내용 넣기 | 완료 | 붙여 넣기 · .txt(UTF-8 · 메모장 ANSI) · .docx(표는 한 행을 한 줄로). 옛 .doc · .hwp 는 2단계 |
| 회의록 서식을 같이 넣기 | 완료 | 기본 3종 + 워드 양식(.docx)이나 양식 글에서 칸 뽑기, 칸 역할로 결정 · Action Item 자리를 앎 |
| 서식에 맞춰 주요 내용 정리 | 완료(반자동 AI + 로컬 LLM + 규칙) | 프롬프트 · 답 읽기(JSON · 칸 이름 묶음 · 표), 메모 근거 점검. 실제 정답 견본과 맞추기는 2단계 |
| 필요 시 로컬 LLM | 완료(선택) | OpenAI 호환 주소로 Ollama · LM Studio · 사내 서버, 모델 목록, <think> 떼기. 모델 권장은 PC 사양 확인 후 |
| 결정 · 담당 · 기한 챙기기 | 완료 | Action Item 모아 보기, 기한 지남 · 3일 안, 담당자별 |
| 회의 녹음 → 글 · 팀 공유 · 알림 | 3단계 | 범위 확정 후 |
